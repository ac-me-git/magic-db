Backup e ripristino

Cosa viene salvato

La collezione, le posizioni, i mazzi e le impostazioni sono un solo file SQLite: collection.db, nella cartella dei dati. Quel file è l'unica cosa che vale la pena salvare. Il catalogo delle carte e le immagini in cache vengono scaricati di nuovo ogni volta che mancano.

Backup automatici

Ogni notte all'ora MAGICDB_BACKUP_HOUR (le 4:00 se non la cambi) AMTG scrive, nella cartella dei backup:

  • collection-YYYYMMDD-HHMMSS.db — una copia completa del database, controllata prima di contare come backup;
  • collection-YYYYMMDD-HHMMSS.csv — la collezione come foglio di calcolo, leggibile senza AMTG.

Se a quell'ora il computer era spento, il backup parte quando è di nuovo acceso. Una collezione vuota non viene salvata.

I backup vecchi vengono rimossi automaticamente. Vengono tenuti:

  • tutti i backup degli ultimi 7 giorni;
  • il più recente di ogni settimana, per le ultime 4 settimane;
  • il più recente di ogni mese, per gli ultimi 12 mesi.

AMTG salva una copia anche prima di ogni operazione rischiosa, e la tiene 30 giorni: pre-import-…db prima di ogni importazione, e pre-migration-…db prima di aggiornare il database a una versione più recente dell'app. Puoi fare un backup in qualsiasi momento, e scaricarne uno qualsiasi, dalla pagina Amministrazione.

Dove finiscono i backup

Se non indichi altro, in backups dentro la cartella dei dati — sullo stesso disco della collezione. Questo ti protegge da un errore, non da un disco rotto o da un computer rubato. Imposta MAGICDB_BACKUP_DIR su una cartella sincronizzata o salvata altrove (una cartella cloud, un NAS):

# Docker: monta una cartella dell'host e punta la variabile lì (vedi compose.yaml)
MAGICDB_BACKUP_DIR=/backups
rem Windows
set MAGICDB_BACKUP_DIR=D:\OneDrive\magic-db-backups
magic-db.exe

Ripristinare

Il ripristino sostituisce l'intera collezione con quella del backup. Si fa a mano, di proposito.

  1. Ferma AMTG (chiudi la sua finestra, oppure docker compose stop).
  2. Nella cartella dei dati, elimina collection.db-wal e collection.db-shm se ci sono. Appartengono al database che stai sostituendo.
  3. Copia il backup che vuoi sopra collection.db: 
    copy /Y backups\collection-20261112-040000.db collection.db
    cp backups/collection-20261112-040000.db collection.db
  4. Riavvia AMTG.

Con Docker e il volume predefinito:

docker compose stop
docker compose run --rm --entrypoint sh magic-db -c \
  "rm -f /data/collection.db-wal /data/collection.db-shm && \
   cp /data/backups/collection-20261112-040000.db /data/collection.db"
docker compose start

Se hai soltanto un'esportazione CSV o JSON, parti da una collezione vuota e ripristinala con Importa — vedi Importa ed esporta. L'esportazione JSON ripristina anche le posizioni vuote e i mazzi; il CSV no.

Spostarsi su un altro computer

Ferma AMTG, copia collection.db (e la cartella backups, se vuoi lo storico) nella cartella dei dati della nuova installazione, e avviala lì. Il catalogo viene scaricato di nuovo da solo.
